# Artist archive prototype

A prototype that turns an unstructured artist CV into a structured, browsable digital archive. Paste in CV lines like "2019, Residency at Villa Medici, Rome" and get a searchable catalogue, a timeline view, and a page per entry, all generated from AI-structured data.

Built with Next.js (App Router), TypeScript, Zod, the Gemini API and the Pexels API. Both have free tiers.

## How it works

Raw CV text goes to Gemini with a fixed response schema. Gemini returns one JSON record per entry: year, type, title, institution, city, country, description, tags, and a short image search query. Zod validates every record, then plain code adds a URL id, fetches a contextual image from Pexels using the AI's query, and flags any record the AI itself wasn't confident about.

Real CVs rarely list one experience per line, a year, a title and a venue often span several lines, so a small grouping step joins them into one entry before anything reaches the AI.

The result is committed as `data/experiences.json` and the public site is built from that file, no API key needed at runtime. `/playground` and `/admin` are the exceptions, they call Gemini live, so they need `GEMINI_API_KEY` set wherever the site is deployed. Nothing typed there gets saved, this prototype has no database.

## Data model

- `year, type, title, institution, city`: read straight from the entry
- `country, description`: filled in by the AI when not explicit (country from a known city, a short neutral summary)
- `tags, imageQuery`: generated by the AI, used for filtering and for the image search
- `sourceText`: the original text, kept verbatim so every record traces back
- `confidence`: high, medium or low, set by the AI
- `needsReview`: true only when confidence isn't high, the one actionable flag
- `id, images`: added by code after the AI call, not by the AI itself

## Pages

- `/` artist profile, stats, links into the archive and the playground
- `/archive` the catalogue, filterable by type and country, grid or timeline view
- `/archive/[slug]` one entry, with the source text and the full JSON record
- `/playground` paste CV lines, get structured output live
- `/admin` artist dashboard, archive stats and a link into the upload tool
- `/admin/ingest` upload a CV (text, PDF, Word, Excel) or paste it, review, generate
- `/method` how the pipeline works

## Run it

```bash
npm install
cp .env.example .env.local     # add GEMINI_API_KEY and PEXELS_API_KEY
npm run extract                # reads data/raw-cv.txt, writes data/experiences.json
npm run dev
```

```bash
npm run extract -- --skip-images       # no Pexels lookup
npm run extract -- path/to/full-cv.txt # a different CV file
```

## Deploy

Push to GitHub, import the repo in Vercel. In the project's environment variables, add `GEMINI_API_KEY` so `/playground` and `/admin` work. `PEXELS_API_KEY` and `GEMINI_MODEL` are optional there, they're only used by the `npm run extract` script, not at runtime.
